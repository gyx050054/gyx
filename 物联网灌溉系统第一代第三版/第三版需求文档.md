## 一、文档目的与范围

### 1.1 目的

本文档定义智能灌溉系统（第一代第三版）的完整需求，作为设备端、ThingsBoard 平台、微服务端、Android 客户端四端开发与验收的唯一依据。

### 1.2 范围

- **设备端**：温湿度计（只上报）、电动阀（内嵌流量计，可远程控制）
- **平台层**：ThingsBoard（MQTT 接入、时序存储、RPC 转发、REST API）
- **服务端**：task-service（注册/强制改密、定时任务冲突检测与调度执行）
- **客户端**：Android App（登录、田块/设备浏览、实时控制、定时任务、任务管理、历史曲线）

### 1.3 术语与缩写

| 术语 | 含义 |
|---|---|
| 遥测（telemetry） | 设备周期性上报的时序数据（温度、湿度、流量等） |
| RPC | ThingsBoard 远程过程调用（oneway：不等待设备回执） |
| 任务（Task） | 用户创建的定时浇水/关水计划 |
| PENDING / RUNNING / COMPLETED / CANCELLED | 任务状态：等待执行 / 执行中 / 已完成 / 已取消 |
| 冲突 | 同一设备在同一时段已有未完成任务 |

### 1.4 参考资料

- 《智能灌溉田块管理APP内部需求.md》（v1.2）
- 《物联网灌溉系统_用户需求文档.md》
- task-service 源码（entity/controller/service）
- ThingsBoard v4.0.1 API 文档

## 二、系统总体描述

### 2.1 系统定位

面向中小型农户的农田灌溉物联网管理平台：实时查看田间设备状态与历史数据，远程控制电动阀，定时自动灌溉。

### 2.2 用户角色

| 角色 | 说明 |
|---|---|
| 管理员/农户 | 登录系统，查看田块信息、管理田间设备、设置浇水任务（本版单角色） |

### 2.3 系统组成（四端）

| 端 | 实现 | 职责 |
|---|---|---|
| 设备端 | 27 台模拟器（Python + paho-mqtt） | 上报遥测、接收并执行 RPC 指令 |
| 平台层 | ThingsBoard v4.0.1（Docker） | MQTT 接入、时序存储、RPC 转发、REST API |
| 微服务端 | task-service（Spring Boot :9300 + MySQL :3306 库 task_service） | 注册/强制改密；任务冲突检测、定时扫描、RPC 触发 |
| 客户端 | kotlin-demo（Kotlin + Compose） | 用户交互，经 REST 与平台层/微服务端通信 |

### 2.4 总体架构与数据流

```
┌────────────┐   MQTT上行(telemetry)   ┌──────────────┐
│  温湿度计   │ ──────────────────────▶ │              │
│ (不可操作)  │                         │  ThingsBoard │
└────────────┘                         │  (v4.0.1)    │
┌────────────┐   MQTT上行(telemetry)   │  时序库       │
│  电动阀     │ ──────────────────────▶ │              │
│ (可操作)    │ ◀────────────────────── │              │
└────────────┘   MQTT下行(RPC指令)      └──────┬───────┘
                                               │ REST API
                 ┌───────────────┐             │ RPC oneway
                 │ task-service  │◀────────────┤
                 │ (:9300)       │             │
                 │ 定时扫描/冲突  │             │
                 │ 检测/注册改密  │             │
                 └───────────────┘             │
                                               ▼
                                        ┌──────────────┐
                                        │ Android APP  │
                                        │ (kotlin-demo)│
                                        └──────────────┘
```

**四类数据流向总览：**

| # | 流向 | 协议 | 说明 |
|---|---|---|---|
| 1 | 设备 → ThingsBoard | MQTT 上行 | 遥测数据（温度/湿度/流量/状态） |
| 2 | ThingsBoard → 设备 | MQTT 下行 | RPC 控制指令（开/关/暂停阀） |
| 3 | APP ↔ ThingsBoard | REST | 读取遥测时序数据、查设备列表、发 RPC 指令 |
| 4 | APP ↔ task-service | REST | 注册/改密、任务增删查（含冲突检测） |

### 2.5 技术栈与运行环境

| 项 | 内容 |
|---|---|
| 设备模拟器 | Python + paho-mqtt，27 台，目录 `物联网灌溉系统第一代第三版/simulators` |
| 平台 | ThingsBoard v4.0.1，Docker 部署（:8080 Web / :1883 MQTT） |
| 微服务端 | Spring Boot（task-service :9300），JDK 17，Maven |
| 数据库 | MySQL（:3306），库 `task_service`，JPA 自动建表 |
| 客户端 | Android，Kotlin + Compose，AVD Pixel_10 |
| 演示账号 | 15079983758@163.com / 147258（9 田块 + 27 台设备） |

### 2.6 关键约束

1. 任务时间间隔最小 **1 分钟**（APP 层保证）
2. 任务冲突时**拒绝创建**（批量任务任一冲突则整体拒绝）
3. 任务取消为**软删除**（置 CANCELLED，不物理删除）
4. 微服务端未配置 Actuator；健康检查看业务接口而非 `/actuator/health`
5. task-service 统一响应结构 `{success, message}`（认证与任务接口一致）

## 三、设备端需求

### 3.1 设备分类

| 设备类型 | 可操作性 | 说明 |
|---|---|---|
| 温湿度计 | ❌ 不可操作 | 仅上报数据，无下行控制 |
| 电动阀（内嵌流量计） | ✅ 可操作 | 远程开/关、定时任务、流量/水压/电量监测、故障自检 |

### 3.2 温湿度计（不可操作设备）

#### 3.2.1 功能概述

仅采集并上报环境温度与湿度；**不订阅任何下行主题，不接收控制指令**。

#### 3.2.2 数据上报（完整定义）

**上报内容字段：**

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `temperature` | float | ✓ | 环境温度（℃） | 28.5 |
| `humidity` | float | ✓ | 环境湿度（%RH） | 65.2 |
| `ts` | long | ✓ | 采集时间戳（毫秒） | 1721800000000 |
| `deviceId` | string | ✓ | 设备唯一标识（UUID） | a1b2c3d4-... |

**上报时机与频率：**
- 设备上电后立即上报第 1 条；此后**每 10 分钟**上报一次
- QoS：1（至少一次）

**发送格式与流向：**
- 协议：MQTT 上行
- 主题：`v1/devices/me/telemetry`
- 方向：设备 → ThingsBoard
- 消息体（JSON）：
```json
{
  "temperature": 28.5,
  "humidity": 65.2,
  "ts": 1721800000000,
  "deviceId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```
- 数据去向：ThingsBoard 接收后写入**时序数据库**（Timeseries Database），供 APP 按 `temperature`/`humidity` 键查询

### 3.3 电动阀（内嵌流量计，可操作设备）

#### 3.3.1 功能概述

支持：远程开启/关闭、即时流量监测（瞬时流量、累计用水量）、管道水压监测、电量监测、故障自检、定时任务控制。**根据阀门工作状态切换上报频率与字段集。**

#### 3.3.2 非工作状态上报（valveState = IDLE）

**上报内容字段：**

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `valveState` | string | ✓ | 开关状态 | "IDLE" |
| `deviceId` | string | ✓ | 设备唯一标识 | "uuid-string" |
| `faultStatus` | boolean | ✓ | 是否故障（true=故障） | false |
| `batteryLevel` | int | ✓ | 电量（0~100%） | 85 |
| `ts` | long | ✓ | 上报时间戳 | 1721800000000 |

**上报频率：** 非工作状态下**每 30 分钟**上报一次（降低功耗）；状态由 IDLE → WORKING 时立即切换上报模式。

**发送格式与流向：**
- 主题：`v1/devices/me/telemetry`；方向：设备 → ThingsBoard；QoS 1
- 消息体：
```json
{
  "valveState": "IDLE",
  "deviceId": "a1b2c3d4-...",
  "faultStatus": false,
  "batteryLevel": 85,
  "ts": 1721800000000
}
```

#### 3.3.3 工作状态上报（valveState = WORKING）

**上报内容字段：**

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `deviceId` | string | ✓ | 设备唯一标识 | "uuid-string" |
| `instantFlow` | float | ✓ | 瞬时流量（L/min） | 12.5 |
| `totalWaterUsage` | float | ✓ | 累计用水量（m³） | 3.24 |
| `waterPressure` | float | ✓ | 管道水压（MPa） | 0.35 |
| `batteryLevel` | int | ✓ | 电量（0~100%） | 85 |
| `ts` | long | ✓ | 上报时间戳 | 1721800000000 |

**上报频率：** 工作状态下**每 10 秒**上报一次（高频率监测）。

**发送格式与流向：**
- 主题：`v1/devices/me/telemetry`；方向：设备 → ThingsBoard；QoS 1
- 消息体：
```json
{
  "deviceId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "instantFlow": 12.5,
  "totalWaterUsage": 3.24,
  "waterPressure": 0.35,
  "batteryLevel": 85,
  "ts": 1721800000000
}
```

#### 3.3.4 下行控制（RPC）

**控制链路：**

```
APP ──REST POST /api/rpc/oneway/{deviceId}──▶ ThingsBoard ──MQTT v1/devices/me/rpc/request/<requestId>──▶ 电动阀
APP ◀────────────────────────────────────── ThingsBoard ◀──MQTT v1/devices/me/rpc/response/<requestId>── 电动阀
```

**步骤一：客户端下发指令**
1. 用户在 APP 点击设备"开启/关闭"
2. APP 调 ThingsBoard RPC API：
   - `POST /api/rpc/oneway/{deviceId}`（oneway：不等待设备回执，快速可靠）
   - 请求体：
```json
{ "method": "setValveState", "params": { "state": true } }
```
   - 参数说明：`method`=方法名；`params.state`：true=开启，false=关闭

**步骤二：ThingsBoard 转发至设备**
- 经 MQTT 下行主题 `v1/devices/me/rpc/request/<requestId>` 下发，消息体与上同

**步骤三：设备执行并回复**
- 设备解析 `method`/`params` → 执行阀门电机操作 → 回复
- MQTT 上行主题：`v1/devices/me/rpc/response/<requestId>`
- 回复消息体：
```json
{ "result": "SUCCESS", "valveState": "WORKING" }
```

**下行控制主题一览：**

| 方向 | MQTT 主题 | 说明 |
|---|---|---|
| 下行 | `v1/devices/me/rpc/request/+` | 服务端 → 设备，发送 RPC 指令 |
| 上行(回复) | `v1/devices/me/rpc/response/<requestId>` | 设备 → 服务端，回复执行结果 |

#### 3.3.5 支持的 RPC 方法（完整清单）

| 方法名 | 参数 | 说明 |
|---|---|---|
| `setValveState` | `{ "state": true/false }` | 开启/关闭阀门（微服务端 openValve/closeValve 封装） |
| `getValveStatus` | `{}` | 查询阀门当前状态（登录校验用） |
| `pauseValve` | `{}` | 暂停任务执行（取消运行中任务时调用） |

## 四、ThingsBoard 平台需求

### 4.1 MQTT 主题总览

**上行（设备 → ThingsBoard）：**

| 设备类型 | MQTT 主题 | 频率 | 数据 |
|---|---|---|---|
| 温湿度计 | `v1/devices/me/telemetry` | 每 10 分钟 | 温度、湿度 |
| 电动阀（未工作） | `v1/devices/me/telemetry` | 每 30 分钟 | 状态、故障、电量 |
| 电动阀（工作中） | `v1/devices/me/telemetry` | 每 10 秒 | 流量、水压、电量 |
| 电动阀（RPC 回复） | `v1/devices/me/rpc/response/<requestId>` | 按需 | RPC 执行结果 |

**下行（ThingsBoard → 设备）：**

| MQTT 主题 | 说明 |
|---|---|
| `v1/devices/me/rpc/request/+` | RPC 远程控制指令 |

### 4.2 遥测存储

- 所有 `v1/devices/me/telemetry` 消息按 JSON 键值写入时序数据库
- 键名即字段名（见第八章字段字典），供 REST 查询

### 4.3 时序数据查询接口（APP 读取规范）

**统一接口：** `GET /api/plugins/telemetry/DEVICE/{deviceId}/values/timeseries`

| 用途 | 参数 | 说明 |
|---|---|---|
| 温湿度最新值 | `keys=temperature,humidity` | limit 默认 1，返回最新值 |
| 温度历史曲线 | `keys=temperature&startTs={start}&endTs={end}&limit=1000` | 按时间范围查历史 |
| 湿度历史曲线 | `keys=humidity&startTs={start}&endTs={end}&limit=1000` | 同上 |
| 阀门状态 | `keys=valveState` | 返回 WORKING / IDLE |
| 瞬时流量 | `keys=instantFlow` | 工作状态有效 |
| 累计用水量 | `keys=totalWaterUsage` | 总用水量 |
| 管道水压 | `keys=waterPressure` | 压力值 |
| 电量 | `keys=batteryLevel` | 剩余百分比 |
| 故障状态 | `keys=faultStatus` | true/false |

**返回格式示例（单键）：**
```json
{
  "valveState": [{ "ts": 1721800000000, "value": "WORKING" }]
}
```

**登录态批量校验：** `GET /api/tenant/deviceInfos?type=VALVE` 获取设备列表 → 逐个查询 `valveState`，返回全部电动阀"是/否工作"标识。

## 五、客户端（APP）功能需求

### 5.1 登录

- 用户未登录时仅可访问登录页
- 登录验证走 **ThingsBoard REST**：`POST /api/auth/login`（username/password → JWT token）
- 登录失败给出明确错误提示
- **登录后自动动作**：校验全部电动阀当前状态（`type=VALVE` 列表 + 逐个查 `valveState`），并在 UI 呈现"工作/未工作"标识
- 返回字段：token（客户端保存，后续请求携带 `Authorization: Bearer <token>`）

### 5.2 田块总览

- 登录后进入田块总览页（卡片/列表）
- 每田块展示：田块名称、设备总数（温湿度计 + 电动阀合计）
- 数据来源：调 ThingsBoard API 查询（设备数量、田块名称、田块 ID）

### 5.3 田块详情 — 设备列表

- 点击田块 → 设备列表页，展示该田块下所有设备

**温湿度计卡片（实时数据）：**
- 设备 ID、当前温度（℃）、当前湿度（%RH）、安装田块、最近一次上报时间
- 数据来源：`GET /api/plugins/telemetry/DEVICE/{deviceId}/values/timeseries?keys=temperature,humidity`

**电动阀卡片（当前状态）：**
- 当前状态（工作/未工作）、电量（%）、设备 ID
- 数据来源：`keys=valveState,batteryLevel`

**刷新机制：** 页面每 **10 秒**自动刷新设备状态。

### 5.4 温度湿度计 — 历史数据

- 点击温湿度计卡片 → 历史数据页
- 以折线图展示历史温度/湿度变化趋势
- 支持时间范围筛选：近 1 小时 / 近 24 小时 / 近 7 天 / 自定义
- 悬停显示具体数值与时间
- 数据来源：`GET /api/plugins/telemetry/DEVICE/{deviceId}/values/timeseries?keys=temperature&startTs=&endTs=&limit=1000`（湿度同理）

### 5.5 电动阀控制

**5.5.1 单设备控制**
- 电动阀卡片带开关按钮，点击开启/关闭
- 实现：APP 调 `POST /api/rpc/oneway/{deviceId}`，body `{"method":"setValveState","params":{"state":true|false}}`
- 操作后明确成功/失败反馈

**5.5.2 批量控制**
- 多选多个电动阀 → 批量操作栏：一键全部开启 / 一键全部关闭
- 实现：对每个选中设备依次发上述 RPC（可并发）
- 批量操作同样有成功/失败反馈

### 5.6 定时浇水任务

**5.6.1 创建（单个）**
- 选择单个设备，设置：目标设备（自动带入）、开始时间（默认立即，可选未来时间）、持续时长（30 分钟/1 小时/2 小时等，最小 1 分钟）
- APP 计算 endTime = startTime + 时长，发请求给微服务端（详见 6.3.1）

**5.6.2 创建（批量）**
- 多选设备 → 同一开始时间/时长，发 `devices` 数组（详见 6.3.1）
- 微服务端先整体冲突预检：任一冲突 → 全部拒绝

**5.6.3 任务冲突处理（用户视角）**
- 同一设备在设定时段已有任务（等待/执行中）→ 新任务拒绝创建
- 批量添加时任一冲突 → 整体拒绝
- 冲突判定：两任务时段有交集（`startTime1 < endTime2 && endTime1 > startTime2`）

### 5.7 任务管理

- 任务管理页展示**全部任务**（含已完成/已取消，保留记录）
- 每任务展示：任务 ID、涉及设备、计划开始时间、计划结束时间、当前状态（等待/执行中/已完成/已取消）
- 取消规则：
  - 未开始（PENDING）→ 直接取消（置 CANCELLED）
  - 进行中（RUNNING）→ **先发暂停 RPC（pauseValve）→ 再置 CANCELLED**
  - 已完成/已取消 → 终态不可取消

### 5.8 设备状态实时更新

- 客户端每 10 秒自动刷新所有设备当前状态（温度、湿度、阀门状态、电量等），无需手动刷新

## 六、微服务端需求（task-service）

### 6.1 模块职责

| 组件 | 职责 |
|---|---|
| AuthController / AuthService | 租户注册、强制改密标记与查询 |
| TaskController / TaskService | 任务创建（含冲突检测）、查询、取消（软删除） |
| TaskScanScheduler | 每 10 秒扫描任务表，到点执行、到期完成 |
| TaskExecutor / RpcTaskExecutor | 执行动作（经 ThingsBoardClient 发 RPC） |
| ThingsBoardClient | TB 登录（JWT 缓存）、oneway RPC 下发 |

### 6.2 数据表设计（task_service 库）

**表名：`tasks`**（索引：deviceId、status）

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT PK 自增 | ✓ | — | 任务 ID |
| `deviceId` | VARCHAR | ✓ | — | 目标设备 ID（ThingsBoard deviceId） |
| `deviceName` | VARCHAR | ✗ | =deviceId | 设备名称（冗余，便于 APP 展示） |
| `startTime` | BIGINT | ✓ | — | 开始时间戳（毫秒） |
| `endTime` | BIGINT | ✓ | — | 结束时间戳（毫秒，须 > startTime） |
| `action` | VARCHAR | ✗ | "on" | 动作：on=开启（默认）/ off=关闭 |
| `status` | ENUM(STRING) | ✗ | PENDING | PENDING/RUNNING/COMPLETED/CANCELLED |
| `tenantId` | VARCHAR | ✗ | null | 所属租户 ID（TB tenantId，UUID 字符串）；null=不分租户 |
| `createdAt` | BIGINT | ✗ | now | 创建时间戳（毫秒） |

**任务状态机：**

```
创建 ──▶ PENDING ──(startTime≤now, RPC执行成功)──▶ RUNNING ──(endTime≤now, 关闭阀门)──▶ COMPLETED
              │                                        │
              └──(取消)──▶ CANCELLED ◀──(先pauseValve再取消)──┘
```

### 6.3 接口设计

> 统一前缀：`http://<host>:9300`；认证接口与任务接口响应统一 `{success, message}`。

#### 6.3.1 创建任务 `POST /api/tasks`

**请求体支持两种形态（由是否有 `devices` 键自动判别）：**

形态一（单个）：
```json
{
  "deviceId": "a1b2c3d4-...",
  "deviceName": "1号阀",
  "startTime": 1721800000000,
  "endTime": 1721803600000,
  "action": "on",
  "tenantId": "46f343a0-90a4-11f1-..."
}
```
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| deviceId | string | ✓ | 目标设备 |
| deviceName | string | ✗ | 缺省取 deviceId |
| startTime | long | ✓ | 毫秒时间戳 |
| endTime | long | ✓ | 须 > startTime |
| action | string | ✗ | on/off，缺省 on |
| tenantId | string | ✗ | APP 从 JWT 解析提交（多租户隔离） |

形态二（批量）：
```json
{
  "devices": [
    { "deviceId": "a...", "startTime": 1721800000000, "endTime": 1721803600000 },
    { "deviceId": "b...", "startTime": 1721800000000, "endTime": 1721803600000 }
  ]
}
```

**处理步骤（实现级）：**
1. 参数预校验（Controller）：单个 deviceId 非空、startTime/endTime 非空且 end > start，否则 400
2. 单个 → `TaskService.createTask`：校验时间 → 冲突检测 `hasConflict` → 无冲突保存并返回新任务
3. 批量 → `TaskService.createTasks`：先对全部设备整体冲突预检，任一冲突返回空列表（全部拒绝）；预检通过后逐个创建
4. 冲突判定 SQL 语义：设备存在 PENDING/RUNNING 任务且 `newStart < oldEnd && newEnd > oldStart`

**响应：**
- 成功（单个）：`{"success":true,"message":"添加成功","taskId":12}`
- 冲突（单个）：HTTP 200 `{"success":false,"message":"设备 xxx 在此时段已有任务，添加失败（冲突）"}`
- 参数非法：HTTP 400 `{"success":false,"message":"参数非法：..."}`
- 批量成功：`{"success":true,"message":"批量添加成功，共 N 条","count":N,"taskIds":[1,2,3]}`
- 批量冲突：`{"success":false,"message":"存在设备时间冲突，全部任务拒绝添加"}`

#### 6.3.2 查询任务列表 `GET /api/tasks`

- 参数：`tenantId`（可选，多租户过滤；缺省返回全部）
- 响应：`List<Task>`（完整任务对象数组，含已完成/已取消）

#### 6.3.3 取消任务 `DELETE /api/tasks/{id}`

**处理步骤（实现级）：**
1. 按 id 查任务；不存在返回 404 `{"success":false,"message":"任务不存在或不可取消"}`
2. 终态（COMPLETED/CANCELLED）不可取消，返回 404 同上
3. RUNNING → 先 `tbClient.pauseValve(deviceId)`（发 `pauseValve` RPC）再置 CANCELLED
4. PENDING → 直接置 CANCELLED（软删除，不物理删除）
- 成功响应：`{"success":true,"message":"任务已取消"}`

#### 6.3.4 删除设备时取消任务 `DELETE /api/tasks/device/{deviceId}`

- APP 删除设备前调用；取消该设备全部 PENDING/RUNNING 任务（RUNNING 先 pauseValve）
- 响应：`{"success":true,"message":"已取消该设备 N 条未完成任务"}`
- 注意：路径两段，与单段 `/{id}` 不冲突

#### 6.3.5 认证接口（/api/auth）

| 接口 | 方法 | 请求 | 响应 | 说明 |
|---|---|---|---|---|
| 注册 | POST `/api/auth/register` | `{"email":"..."}` | `{"success":true,"message":"注册成功，请登录"}` | 默认密码 123456 + 登记强制改密；邮箱格式错 400；重复 409 |
| 查询是否强制改密 | GET `/api/auth/must-change-password?email=...` | — | `{"success":true,"message":"需要改密","mustChange":true}` | 登录后调用，决定是否弹改密 |
| 登记强制改密 | POST `/api/auth/mark-must-change` | `{"email":"..."}` | `{"success":true,"message":"已登记强制改密"}` | 员工账号创建后调用 |
| 标记已改密 | POST `/api/auth/pwd-changed` | `{"email":"..."}` | `{"success":true,"message":"改密标记已清除"}` | 改密成功后调用 |

**注册流程（实现级）：**
1. APP 提交邮箱 → AuthService 校验格式（非法 400）
2. 调用 ThingsBoard 创建租户（重复则 409"该邮箱已注册"）
3. 默认密码 123456，登记强制改密 → 返回成功
4. 用户登录后：查 `must-change-password` → 必须改密 → 改完调 `pwd-changed` 清除标记

### 6.4 业务规则汇总

| 规则 | 说明 |
|---|---|
| 冲突检测 | 同设备、时段相交（`newStart<oldEnd && newEnd>oldStart`）、对方为 PENDING/RUNNING |
| 批量原子性 | 任一设备冲突 → 全部拒绝创建 |
| 最小间隔 | 1 分钟（APP 保证） |
| 软删除 | 取消只改状态为 CANCELLED，不物理删除 |
| 执行失败重试 | RPC 执行失败的任务保持 PENDING，下一轮扫描自动重试（当前无限重试） |
| 状态切换条件 | 执行成功才置 RUNNING；到期执行收尾后才置 COMPLETED |

### 6.5 定时扫描调度（TaskScanScheduler）

- 周期：每 **10 秒**（配置项 `task.scan-interval-ms`，默认 10000，可调）
- 每轮两件事：
  1. **执行到点任务**：查 `PENDING 且 startTime <= now` → `taskExecutor.executeStart`（发开阀/关阀 RPC）→ 成功置 RUNNING、失败保持 PENDING 下轮重试
  2. **到期自动完成**：查 `RUNNING 且 endTime <= now` → `taskExecutor.executeFinish`（发关阀 RPC 收尾）→ 置 COMPLETED（保留记录）

### 6.6 ThingsBoard RPC 客户端（ThingsBoardClient）

**登录与 JWT：**
- `POST {baseUrl}/api/auth/login`，body `{"username","password"}` → 取 `token`
- 缓存策略：token 有效期按 90 分钟计，剩余不足 60 秒时线程安全地重新登录（synchronized）
- 配置：`thingsboard.rpc-timeout-ms`（连接/读取超时，默认 10 秒）

**RPC 下发：**
- `POST {baseUrl}/api/rpc/oneway/{deviceId}`，Header `Authorization: Bearer <token>`，body `{"method":"...","params":{...}}`
- 2xx 视为下发成功
- 业务封装：`openValve`（setValveState,state=true）、`closeValve`（setValveState,state=false）、`pauseValve`（pauseValve,{}）

## 七、端到端数据流（分场景）

### 场景 A：设备遥测上行
```
设备 ──MQTT v1/devices/me/telemetry (JSON遥测)──▶ ThingsBoard ──写入时序库──▶ APP定时GET /api/plugins/telemetry/DEVICE/{id}/values/timeseries?keys=... (Bearer token) ◀──返回最新/历史值
```

### 场景 B：用户控制阀门（即时）
```
APP ──POST /api/rpc/oneway/{deviceId} {method:setValveState, params:{state}}──▶ ThingsBoard
    ──MQTT v1/devices/me/rpc/request/<id>──▶ 设备执行
设备 ──MQTT v1/devices/me/rpc/response/<id> {result:SUCCESS, valveState}──▶ ThingsBoard
```

### 场景 C：创建定时任务
```
APP ──POST /api/tasks (deviceId/startTime/endTime/action/tenantId)──▶ task-service
task-service ──查 tasks 表冲突──▶ 无冲突 ──INSERT tasks(PENDING)──▶ 返回 {success:true, taskId}
```

### 场景 D：任务自动执行（定时扫描）
```
task-service TaskScanScheduler 每10秒：
  查 PENDING 且 startTime<=now ──▶ ThingsBoardClient.sendRpc(setValveState)──▶ ThingsBoard ──MQTT──▶ 设备开阀
  置 RUNNING
  查 RUNNING 且 endTime<=now ──▶ sendRpc(setValveState,state=false)──▶ 设备关阀
  置 COMPLETED（记录保留）
```

### 场景 E：取消任务
```
PENDING：APP ──DELETE /api/tasks/{id}──▶ task-service 直接置 CANCELLED
RUNNING：task-service 先 sendRpc(pauseValve) ──▶ ThingsBoard ──▶ 设备暂停；再置 CANCELLED
```

### 场景 F：注册/登录/改密
```
注册：APP ──POST /api/auth/register {email}──▶ task-service ──▶ ThingsBoard 建租户(密码123456+强制改密标记)
登录：APP ──POST /api/auth/login──▶ ThingsBoard 拿 JWT
改密判断：APP ──GET /api/auth/must-change-password?email=──▶ task-service → mustChange=true
改密完成：APP ──POST /api/auth/pwd-changed {email}──▶ task-service 清除标记
```

## 九、异常与边界

| 场景 | 行为 |
|---|---|
| 任务时间参数非法（end≤start） | 400，拒绝创建 |
| 设备冲突 | 单个：返回 success:false；批量：整体拒绝 |
| 取消终态任务 | 404，不可取消 |
| 设备离线导致 RPC 失败 | 任务保持 PENDING，下轮重试；APP 侧提示控制失败 |
| TB 不可达（注册/登录） | 500"注册失败，请稍后重试" |
| 重复注册邮箱 | 409"该邮箱已注册" |
| 扫描周期过密 | 通过 `task.scan-interval-ms` 调整，不改代码 |
