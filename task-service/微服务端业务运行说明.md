## 1. 定时任务（核心业务）

**触发**：用户在 App 给某个设备设定时任务 → 到点自动开/关阀门。

### 场景 A1：创建任务（单个/批量）
| 顺序 | 文件 | 做什么 |
|---|---|---|
| 1 | `App` | 用户选择设备+时间段 → `POST /api/tasks`（单条）或带 `devices[]`（批量） |
| 2 | `controller/TaskController.create` | 读请求体：`deviceId/deviceName/startTime/endTime/action/tenantId`；`has("devices")` 则走批量，否则单条 |
| 3 | `controller/TaskController.createSingle` | 校验参数（deviceId/start/end 必填、end>start）；解析 DAILY 参数（repeatMode/dailyHour/durationMinutes）；调 `taskService.createTask(...)` |
| 3b | `TaskController.createBatch` | 把 devices 数组转成 `List<TaskDraft>`，逐个校验，调 `taskService.createTasks(drafts)` |
| 4 | `service/TaskService.createTask` | **冲突检测**：`hasConflict`（同设备 PENDING/RUNNING 且 `s1<e2 && e1>s2`）；或 `dailyOverlapsOnce`/`hasDailyConflict`；无冲突则 `taskRepository.save(t)` 落库，状态 PENDING |
| 4b | `TaskService.createTasks` | **整体冲突预检**：任一设备冲突 → 返回空列表（全部拒绝）；通过则逐个 createTask |
| 5 | `repository/TaskRepository.findConflicts` | 用时间交集条件查该设备活跃任务（`@Query` 派生） |
| 6 | `entity/Task` | 任务实体落库（id/deviceId/startTime/endTime/action/status/tenantId/repeatMode/dailyHour/durationMinutes/createdAt） |

**数据流**：App → Controller 解析 → Service 冲突判断 → Repository 查库 → 冲突则拒、无冲突则 save → 返回 `{success,message,taskId}`。

### 场景 A2：扫描执行（每 10 秒）
| 顺序 | 文件 | 做什么 |
|---|---|---|
| 1 | `service/TaskScanScheduler.scanAndExecute` | `@Scheduled(fixedDelayString="${task.scan-interval-ms:10000}")` 每 10 秒触发 |
| 2 | `TaskScanScheduler` ① | `findByStatusAndStartTimeLessThanEqual(PENDING, now)` 捞到点任务 → `taskExecutor.executeStart(t)` 开/关阀 → 成功置 `RUNNING`、保存；失败保持 PENDING（下轮重试） |
| 3 | `TaskScanScheduler` ② | `findByStatusAndEndTimeLessThanEqual(RUNNING, now)` 捞超时任务 → `executeFinish(t)` 关阀 → 置 `COMPLETED`（保留记录） |
| 4 | `service/executor/RpcTaskExecutor.executeStart/executeFinish` | 依据 `t.getAction()`（on/off）调 `thingsBoardClient` 的 RPC（openValve/closeValve） |
| 5 | `service/ThingsBoardClient` | 取租户管理员 **JWT（缓存90分钟）** → `POST /api/rpc/oneway/{deviceId}` `{method:"setValveState",params:{state:true/false}}` → TB 经 MQTT 下发 |
| 6 | 设备(模拟器) | 收到 RPC 执行开关阀，WORKING 后每 10 秒上报 instantFlow/用水量/水压 |

**数据流**：定时器 → 查库拿任务 → 执行器调 TB RPC → 设备开关 → 状态流转 PENDING→RUNNING→COMPLETED。

### 场景 A3：取消任务 / 删除设备
| 顺序 | 文件 | 做什么 |
|---|---|---|
| 1 | `TaskController.delete / cancelByDevice` | `DELETE /api/tasks/{id}` 或 `DELETE /api/tasks/device/{deviceId}` |
| 2 | `TaskService.cancelTask` | 终态（COMPLETED/CANCELLED）不可取消；`RUNNING` 先 `tbClient.pauseValve()` 暂停 → 置 `CANCELLED` 保存（软删除） |
| 2b | `TaskService.cancelTasksByDevice` | 取该设备 PENDING/RUNNING 任务，每个运行中先 pause，全部置 CANCELLED |
| 3 | `ThingsBoardClient.pauseValve` | 调 TB RPC `pauseValve` |

**数据流**：删除 → Service 软删 → 运行中先暂停设备 → 状态 CANCELLED。

## 2. 每天自动浇水（第三代功能一）

**触发**：用户建 `repeatMode=DAILY` 任务（每天某小时自动浇 X 分钟）。

| 顺序 | 文件 | 做什么 |
|---|---|---|
| 1 | `TaskController.createSingle` | 解析 `repeatMode=DAILY + dailyHour(0-23) + durationMinutes(>0)`，校验后调 `createTask` |
| 2 | `TaskService.createTask(DAILY)` | 校验 dailyHour/durationMinutes；`hasDailyConflict`（同设备已有活跃 DAILY 或 RUNNING 一次性则拒）；用当天窗口 `dailyWindow(dailyHour, durationMinutes)` 作为 start/end 占位落库，状态 PENDING（常驻"闹钟"） |
| 3 | `service/DailyTaskService.processDaily` | 由 `TaskScanScheduler` ③ 调用：`findByRepeatModeAndStatus(DAILY, PENDING)` → 到 `dailyHour` 点开浇（RPC）→ 写 `task_runs` 按 `taskId+runDate` 去重 → `durationMinutes` 到点关浇 → 降雨概率≥80% 跳过（SKIPPED_WEATHER） |
| 4 | `entity/TaskRun` + `repository/TaskRunRepository` | 每天任务执行流水：`taskId/runDate/status/startTime/endTime`，用于 App 展示"昨天浇没浇/是否因雨跳过" |
| 5 | `TaskController.runs` `GET /api/tasks/{id}/runs` | 查某任务全部流水（`taskRunRepository.findByTaskIdOrderByRunDateDesc`） |

> ⚠ **已知缺陷**：`TaskScanScheduler` ① 会把 DAILY 任务当普通到点任务捞到并置 RUNNING，导致 `processDaily` 匹配不到 → `task_runs` 未写入、天气跳过/按日去重失效。**待修**：让 ①/② 跳过 `repeatMode=DAILY`，DAILY 全交给 `processDaily`。

**数据流**：建 DAILY → 扫描器 → `DailyTaskService` 按日调度 → 开/关浇 RPC → 写流水。

## 3. 自定义告警（第三代功能四，自研引擎）

**触发**：规则命中（某设备遥测值超过阈值）。

| 顺序 | 文件 | 做什么 |
|---|---|---|
| 1 | `controller/AlarmController` | `/api/alarms/**`：规则 CRUD、启用/停用、告警列表、`unread-count`、`ack` 确认 |
| 2 | `service/AlarmService` | 规则增删改查；`queryRules` → 每 30 秒扫遥测判阈值 |
| 3 | `service/AlarmScanScheduler` | `@Scheduled(fixedDelayString="${alarm.scan-interval-ms:30000}")` 每 30 秒触发 `AlarmService.scan` |
| 4 | `ThingsBoardClient.latestTelemetry` | 查设备最新遥测（如 soilSalinity/soilPh/temperature） |
| 5 | `entity/AlarmRule` + `AlarmRuleRepository` | 规则实体/查库（deviceType/telemetryKey/operator/阈值/enabled） |
| 6 | `entity/AlarmRecord` + `AlarmRecordRepository` | 告警记录：命中→ACTIVE；恢复→RESOLVED；确认→ACKNOWLEDGED；未确认计数 |
| 7 | `AlarmController.unread-count` | 查未确认 ACTIVE 告警数，供 App 红点 |
| 8 | `AlarmController.ack` | 单条确认 → ACTIVE→ACKNOWLEDGED，未读数 -1 |

**数据流**：定时扫遥测 → 规则命中 → 建/刷新告警记录 → App 轮询 `unread-count` 显示红点 → 用户确认。

## 4. 注册 / 认证 / 强制改密（第二版多租户）

**触发**：用户在 App 注册新账号。

| 顺序 | 文件 | 做什么 |
|---|---|---|
| 1 | `controller/AuthController` | `POST /api/auth/register`、`GET must-change-password`、`POST pwd-changed`、`POST mark-must-change`，统一 `{success,message}` |
| 2 | `service/AuthService.register` | 编排：**建租户 → 建租户管理员 → 激活设默认密码 123456 → 登记强制改密标记** |
| 3 | `service/ThingsBoardAdminClient` | 用 **SysAdmin JWT** 调 TB：创建租户、创建租户用户、激活（解析 activationLinkInfo 里的 activateToken） |
| 4 | `config/ThingsBoardProperties` | 读取 `thingsboard.baseUrl/username/password/sysadminUsername/sysadminPassword/rpcTimeoutMs` |
| 5 | `entity/TenantCredential` + `TenantCredentialRepository` | 存租户 ID 与凭据（多租户隔离用） |
| 6 | `entity/UserPwdFlag` + `UserPwdFlagRepository` | 邮箱为主键的 `mustChangePassword` 标记；首次登录必须改密 |

**数据流**：注册 → AuthService 协调 TB(建租户/管理员/激活) + 本地库(记改密标记/租户凭证) → App 自动登录 → 强制改密。

## 8. 一次完整数据流（浇一次水）
1. 用户在 App 开关阀 → `POST /api/rpc/oneway/{deviceId}` `setValveState{state:true}` → TB MQTT 下发 → 阀门执行。
2. 用户设定时任务 → `POST /api/tasks` → 冲突检测 → PENDING 入库。
3. 每 10 秒 `TaskScanScheduler` 扫到点任务 → `RpcTaskExecutor` 开阀 RPC → RUNNING。
4. 到时关阀 → COMPLETED；App 每 10 秒轮询遥测刷卡片。
